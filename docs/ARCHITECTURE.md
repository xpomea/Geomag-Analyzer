## 1. Контекст, цели и персоны пользователей

Программная система разрабатывается в рамках магистерской диссертации (ОНУ) для комплексного исследования четырёх геомагнитных бурь октября 2026 года по данным наземных магнитометров Европы и Канады (`INTERMAGNET`), параметрам солнечного ветра и ММП (`SOLAR-1` в точке L1, `OMNI` на BSN) и потоку космических лучей (`OULU NM`).

### 1.2. Обоснование выбора Варианта 1 и отказ от альтернатив

Выбор стека **Вариант 1** (`FastAPI + NumPy/SciPy + React/TS + pywebview`) обусловлен следующими инженерными и научными факторами:
1. **Производительность научных вычислений без переусложнения:** прямые замеры `NumPy`/`SciPy` показывают, что `FFT+IFFT` для `49 станций × 3 компоненты × 17 280 точек` выполняется за **88,3 мс**, кросс-спектр Уэлча для **всех 1 176 пар станций** (1 окно, 4 320 точек) — за **50,2 мс**, а динамический кросс-спектр всех 1 176 пар на 288 шагах — за **1,07 с**. Ядро `NumPy`/`SciPy` уже опирается на C/Fortran (`PocketFFT`, `OpenBLAS`, `sosfilt`), поэтому переписывание математики на Rust (`Вариант 3: Tauri + Rust`) дало бы ускорение порядка лишь $1.2\text{–}2.5\times$ ценой $2.5\text{–}3\times$ роста трудоёмкости (ручная реализация Баттерворта `SOS`, $I_0$ Кайзера, DPSS, обратной бета-функции $B_\alpha^{-1}(n-1, 3/2)$, линковка `libnetcdf`/`libhdf5` под Windows и отдельный HTTP-адаптер для веб-режима).
2. **Двойной режим «Настольное приложение $\leftrightarrow$ Веб-сервис»:** `FastAPI` изначально работает по HTTP/WebSocket. Для десктопа интерфейс открывается в `pywebview` (использует встроенный в Windows компонент Microsoft Edge `WebView2`, не требуя тащить ~200 МБ Chromium как Electron), а для веб-сервиса та же пара `FastAPI + static React` запускается под `uvicorn` (`--workers 1`) без `pywebview`. В отличие от `PySide6/Qt` (`Вариант 2`), веб-режим не требует переделки интерфейса, а интерактивная 49-станционная географическая карта на **`D3-geo` + локальном `world-110m.topojson`** работает на 100% офлайн и не зависит от проблемных под `PyInstaller` C-библиотек `Cartopy`/`GEOS`/`PROJ`.
3. **Управляемость долгих вычислений:** многоминутные задачи (`XWT`/`WTC` с 300–1000 суррогатами Монте-Карло и калибровка эффективного $n$) не блокируют UI и не теряются при обновлении вкладки браузера (в отличие от чисто браузерного `Варианта 4a`), а исполняются в изолированном пуле процессов `ProcessPoolExecutor` с кэшированием на диск.
4. **Отказ от антипаттернов развёртывания:** исключены `Docker/WSL2` (проблемы прав и виртуализации на Windows), ручной `venv + CLI`, `Streamlit` (перезапуск всего скрипта при взаимодействии) и `PyInstaller --onefile` (задержка распаковки 10–15 с и частые ложные срабатывания Windows Defender).

### 3.1. Двойной режим запуска (Desktop и Web-Service)

1. **Настольный режим (по умолчанию на Windows):**
   - Точка входа `launcher.py` обязательно вызывает **`multiprocessing.freeze_support()`** под `if __name__ == "__main__":` (обязательно для механизма `spawn` в `PyInstaller --onedir` на Windows), находит свободный локальный порт `127.0.0.1:<port>`, запускает `uvicorn` (`--workers 1`) в фоновом потоке и открывает окно `pywebview` (рендеринг через системный `Edge WebView2`).
   - Внутри дочерних процессов `ProcessPoolExecutor` принудительно выставляются однопоточные ограничения BLAS (`OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, `NUMEXPR_NUM_THREADS=1`), чтобы исключить переподписку потоков $(N_{\text{cpu}}-1) \cdot N_{\text{cpu}}$.
   - **Механизм фолбэка (~20 строк кода):** если `WebView2 Runtime` отсутствует (старая версия Windows) или передан ключ `--browser`, лаунчер автоматически открывает системный браузер по умолчанию на `http://127.0.0.1:<port>?token=<bootstrap_token>`.
   - **Корректное завершение в обоих режимах:** при закрытии окна `pywebview` сервер `FastAPI` и воркеры `ProcessPoolExecutor` останавливаются штатно; для режима `--browser` при `console=False` (без окна терминала) в UI встроена кнопка **«Остановить сервер / Выход»** (`POST /api/shutdown` с session-token) и/или иконка выхода в системном трее Windows.
2. **Режим веб-сервиса (Headless Server Mode):**
   - Та же кодовая база запускается командой `uvicorn geomag_api.main:app --host 0.0.0.0 --port 8000 --workers 1` (без импорта `pywebview`) за reverse proxy (`Nginx`/`Caddy`, терминирующим TLS и проксирующим WebSocket-соединения `Upgrade/Connection`). При использовании `JobManager` в памяти процесса обязателен `--workers 1`; горизонтальное масштабирование `>1` API-воркера допускается только при выносе очереди задач и токенов отмены во внешний брокер/БД (`Redis`/SQLite).
   - В серверном режиме активируются конфигурационные ограничения: лимит числа одновременных MC-задач в `ProcessPoolExecutor`, квота на число суррогатов и общий дисковый `user_cache/`, разделяемый между сессиями.

## 4. Слой ETL и бинарного кэширования

В соответствии с оценкой организации данных (см. `DATA_ORGANIZATION_ASSESSMENT.md`) чтение сырых текстовых файлов вынесено в однократно запускаемый (или запускаемый при подключении нового датасета) детерминированный ETL-конвейер.

### 4.1. Конвейер нормализации (`geomag_etl/`)

1. **Индексация и воссоздание манифеста:** сканирование `GeoMag_Storms_Dataset_Oct-2026`, верификация контрольных сумм `SHA-256`, запись таблицы всех 483 файлов в `catalog.sqlite` (`raw_manifest`), что полностью компенсирует отсутствующий `manifest.csv`.
2. **Обработка `INTERMAGNET_1min`:**
   - Парсер заголовка IAGA-2002; определение формата строго по `Reported` (`XYZF` или `HDZF`) и заголовкам столбцов (игнорируя ошибочный `Sensor Orientation` у 10 `XYZF` станций и `LON`).
   - Замена `99999.00` и `88888.00` на `np.nan`.
   - При `HDZF`: перевод $D_{\text{рад}} = \frac{\pi}{180}\frac{D_{\text{угл.мин}}}{60}$, затем $X = H\cos D, Y = H\sin D$ (формула 2 `.docx`).
   - Построение **совместной маски валидности** `is_valid_xyz = isfinite(X) & isfinite(Y) & isfinite(Z)` — скалярный столбец `F` хранится отдельно (`f_scalar_nT`) и **не участвует** в браковании точек (`87 592` строки с пропуском только в `F`).
   - **Контроль базовой линии (`has_baseline`):** автоматическая проверка по 3D-модулю вектора `|meanXYZ| >= 10000 нТл` фиксирует в `stations` признак `has_baseline = False` для безбазисных `Variation`-станций (`GCK` — `469,3 нТл`, `NCK` — `2 343,9 нТл`), отделяя их от всех 47 полнополевых обсерваторий (`>= 35 789,8 нТл`) и не допуская ложной отбраковки арктической обсерватории `Canada/RES` (`74.69°N`), где `H_mean = 3 369,5 нТл < 5 000 нТл`, но `|meanXYZ| = 57 372,7 нТл` (полное поле). Это блокирует автоматический расчёт $D_0$ по формуле (4) без явного ввода $D_0$ пользователем.
   - **Опциональный / диагностический деспайкинг (`was_despiked`):** обнаружение единичных немаркированных инструментальных выбросов (напр., `VAL 2026-10-09 10:39Z` `-1 250,51 нТл` с отскоком `+1 212,10 нТл`: `44 179,12 -> 42 928,61 -> 44 140,71 нТл`; `OTT 2026-10-22 13:48Z` `-350,91 / +355,66 нТл`: `49 955,66 -> 49 604,75 -> 49 960,41 нТл`) фильтром `MAD/Hampel` по 1-й разности с **обязательной кросс-станционной защитой** (выброс не маскируется, если соседние обсерватории в том же временном окне регистрируют синхронный скачок `SC`/`SI`).
   - Применение правил §3.2: линейная интерполяция разрывов длиной $\le 3$ отсчётов с сохранением флага `is_interpolated`; отметки окон с $>5\%$ пропусков или разрывом $>3$ отсчётов.
   - **Сшивка штормовых блоков:** смежные сутки объединяются в 4 непрерывных массива (`storm_20261004_05`: 2880 мин; `storm_20261009_11`: 4320 мин; `storm_20261021_23`: 4320 мин; `storm_20261030_31`: 2880 мин), чтобы избежать потери $2 T_{\text{cut}}$ на внутренних суточных границах.
   - Нормализация долгот `lon_deg = lon - 360.0 if lon > 180.0 else lon`; раздельное хранение пофайлового качества `v/q/p` и метаданных координат `SOD` (`2026-10-04..11` `v` `67.400, 026.600`, `10-23` `p` `67.370, 026.630`, `10-30..31` `p` `67.400, 026.600`).
3. **Обработка `SOLAR-1` (`MAG` + `SWiPS`):**
   - `SWiPS` CSV: сортировка записей по возрастанию `time_utc` для устранения обратных скачков (`-27.962 с` на `flags=11`); фильтрация по умолчанию **`flags == 0`** + физические пороги разумности (маскирование аномальных выбросов на `flags=8/1` вроде `n = 119,1 см⁻³`, `Pdyn = 56,90 нПа` / `5,690×10⁻⁸ Па` в `15:04:01Z` 10 окт. — при этом `48,79 нПа` фиксируется отдельно при `n = 111,48 см⁻³` — и `T = 4.63×10⁶ K` 11 окт., с возможностью выбора пользовательской маски флагов и явным предупреждением о недокументированности битов `{0,1,2,3,8,10,11,16}`); перевод давления `proton_dyn_pressure_Pa * 1e9 -> nPa`.
   - **Детерминированная привязка `~60.055 с -> [:, 00s]` UTC:** для каждой регулярной минуты `t_k` выбирается ближайший валидный скан в окне `±30 с` (при точном равенстве расстояний tie-break в пользу более ранней метки времени); пустые бины (возникающие каждые ~18 мин из-за дрейфа шага) сохраняются как `NaN`, а исходный сдвиг сохраняется в метаданных.
   - `MAG` CSV: реиндексация на полную минутную сетку с заполнением опущенных строк (`Oct 11/21/30/31`) значением `NaN`.
   - Явная фиксация временной шкалы `time_frame = "L1"`. При отображении и корреляционном анализе в UI/бэкенде применяется **баллистический сдвиг времени** на Землю с референсной дистанцией `L1-BSN` по умолчанию ($\Delta X_{\text{ref}} = X_{\text{L1}} - X_{\text{BSN}} \approx 1.4 \times 10^6\text{ км} \approx 220 R_E$ либо эфемеридная координата):
     $$\Delta t_{\text{prop}}(t) \approx \frac{\Delta X_{\text{ref}}}{|V_x^{\text{smooth}}(t)|} \quad (\text{типично } 30\text{–}60\text{ мин}),$$
     где $V_x^{\text{smooth}}(t)$ предварительно сглаживается (скользящая медиана) с монотонной коррекцией $t + \Delta t_{\text{prop}}(t)$, исключающей инверсию порядка отсчётов на резких скачках скорости; поддерживается переключение на постоянный пользовательский лаг.
   - Опциональное чтение `NetCDF-3` через `scipy.io.netcdf_file(..., mmap=False)`: в `oe_mag-l3` переменная `flags` константно равна `-2147483647` (`0x80000001`) во всех 849 814 1-с отсчётах и непригодна как поотсчётная маска качества (`.nc` читается только ради 1-с `b_gse_sec`/`b_gsm_sec` или некалиброванных альфа-моментов), а в `oe_swips-l2` 23 из 49 переменных равны `-9999.0`.
4. **Обработка `OMNI_1min` и `OULU NM`:**
   - `OMNI`: **строго поколоночный позиционный парсер** по спецификации `HRO_format.txt` (46 столбцов), замена индивидуальных маркеров (`99`, `999`, `99.9`, `999.9`, `99999` и др.) на `NaN` по схеме столбца (без глобальной строковой замены, чтобы не повредить `AE_nT = 99`/`999`), регистрация `time_frame = "BSN"` и таблицы покрытия только за `Oct 4–5`, `9–11`.
   - `OULU`: слияние 4 многодневных CSV в единый `oulu_nm_1min.parquet` с вычислением относительных вариаций $\Delta N / N_0$ (%) относительно спокойного базового уровня для анализа Форбуш-понижений и подключением внешней карточки метаданных станции.

## 5. Вычислительное ядро (`geomag_core`) и верификация по `.docx`

Ядро `geomag_core` реализуется как **автономный чистый Python-пакет** (`NumPy` + `SciPy`, без зависимостей от `FastAPI` или UI). Оно используется одновременно веб-бэкендом, воркерами `ProcessPoolExecutor` и CLI-скриптами подготовки таблиц/графиков диссертации, гарантируя полную численную идентичность.

### 5.1. Конвенции и диапазоны (§§1–3 `.docx`)

- Временна́я зависимость $e^{+i\omega t}$; прямое ДПФ $F(f) = \sum_n x_n e^{-i 2\pi f n \Delta t}$ (совпадает с `numpy.fft.fft`).
- Спектральная матрица $S_{ij} = \langle F_i F_j^* \rangle$; знак $\operatorname{Im} S_{xy} > 0$ соответствует вращению вектора $X \to Y$ (по часовой стрелке сверху при $+Z$ вниз); азимут $\psi \in (-90^\circ, 90^\circ]$ от $X$ (Север) к $Y$ (Восток).
- **Диапазоны (формула 1):** $\text{Pc5} = [150, 600]\text{ с}$ ($1.667\text{–}6.667\text{ мГц}$); $\text{Pc6} = (600, T_{\max}]\text{ с}$ (по умолчанию $T_{\max} = 1800\text{ с} \to 0.556\text{ мГц}$, поддерживается $900\text{ с}$ и пользовательский выбор). Предел Найквиста для $\Delta t = 60\text{ с}$: $120\text{ с}$ ($8.333\text{ мГц}$). В отчётах и подсказках UI учитывается затухание 19-точечного фильтра Гаусса INTERMAGNET на нижней границе Pc5 ($|H(150\text{ с})| = 0.805$).
- **Поворот в локальную магнитную СК (формулы 4–5):** опциональный поворот $(X, Y) \to (X_m, Y_m)$ (или $S_m = R S R^T$) на единое суточное спокойное склонение $D_0 = \operatorname{atan2}(\langle Y \rangle_{\text{сут}}, \langle X \rangle_{\text{сут}})$ для корректного суточного сопоставления без искажения $I, V, p$. Для станций с `has_baseline == False` (`|meanXYZ| < 10000 нТл`: безбазисные вариации `GCK` `469,3 нТл` и `NCK` `2 343,9 нТл`; тогда как у арктической полнополевой обсерватории `Canada/RES` `74.69°N` при `H_mean = 3 369,5 нТл < 5 000 нТл` полный вектор `|meanXYZ| = 57 372,7 нТл`, и все 47 полнополевых станций имеют `|meanXYZ| >= 35 789,8 нТл`) автоматический расчёт $D_0$ блокируется (если пользователь явно не задал внешнее значение $D_0$).
- **Защита от инструментальных выбросов (QC):** перед фильтрацией доступна опциональная/диагностическая деспайк-очистка (`MAD/Hampel` по 1-й разности с кросс-станционным подтверждением для сохранения реальных `SC`/`SI`), предотвращающая звон фильтров на выбросах уровня `VAL` (`-1 250,51 нТл`, отскок `+1 212,10 нТл`: `44 179,12 -> 42 928,61 -> 44 140,71 нТл`) и `OTT` (`-350,91 / +355,66 нТл`: `49 955,66 -> 49 604,75 -> 49 960,41 нТл`).

### 5.3. Поляризация Стокса, 3D-параметры и статистические пороги

- **2D Стокс (§5, формулы 12–19):** вычисление $I, Q, U, V$, $A = \sqrt{Q^2+U^2}$, $R = \sqrt{Q^2+U^2+V^2}$, степени поляризации $p = R/I$, линейной/циркулярной долей $p_L, p_C$, азимута $\psi = \frac{1}{2}\operatorname{atan2}(U, Q)$, угла эллиптичности $\chi = \frac{1}{2}\arcsin(V/R)$, отношения осей $\varepsilon = \tan\chi = V/(R+A)$, когерентности $\gamma^2 = |S_{xy}|^2/(S_{xx}S_{yy})$ и фазы $\arg S_{xy}$.
- **Инвариант агрегации (§5.7):** при объединении окон, суток или станций усредняются **только** матрицы $S$ или параметры Стокса $(I, Q, U, V)$, но никогда углы $\psi, \chi$ или $p$ напрямую.
- **3D поляризация (§6, формулы 26–29):** степень поляризации Самсона $P$ (формула 26), вектор вращения Минса $n_v = (\operatorname{Im}S_{yz}, -\operatorname{Im}S_{xz}, \operatorname{Im}S_{xy})^T$ (формула 27), углы нормали $\theta, \phi_n$ (формула 28), собственные значения $\lambda_1 \ge \lambda_2 \ge \lambda_3$ матрицы $\operatorname{Re} S$ с вычитанием изотропного шума $b/a = \sqrt{(\lambda_2-\lambda_3)/(\lambda_1-\lambda_3)}$ и $s = 2|n_v|/\operatorname{tr} S$ (формула 29).
- **Эффективное число степеней свободы $n$ и пороги (§5.9, §9.4):**
  - В Варианте A $n$ определяется по калибровочной таблице (Таблица 3) или прямой симуляцией Монте-Карло ($n = \frac{1}{2}(3/E[\hat{p}^2] - 1)$); в Варианте B — строго по формуле (48) `.docx`:
    $$n = T_w \cdot \frac{\left(\int_0^\infty P(f)\,df\right)^2}{\int_0^\infty P^2(f)\,df}, \qquad B_{\text{eff}} = \frac{\left(\int_0^\infty P(f)\,df\right)^2}{\int_0^\infty P^2(f)\,df},$$
    где $P(f) = A^2(f)\,S_0(f)$ (например, для 18-ч плоского спектра Pc5 с `FFT`-маской $B_{\text{eff}} \approx 5.58\text{ мГц}$ и $n \approx 362$; при весовом окне $w_n$ вместо $T_w$ подставляется $\Delta t' (\sum w_n)^2 / \sum w_n^2$). Значение $n$ строго инвариантно к оверсэмплингу $m$, **никогда** не подставляется $mN_w$.
  - Критические пороги при уровне значимости $\alpha \in \{0.05, 0.01\}$ (формулы 24–25, Таблица 5):
    $$p_{\text{crit}} = \sqrt{1 - B_\alpha^{-1}\!\left(n-1, \frac{3}{2}\right)} \quad (\text{через }\texttt{scipy.stats.beta.ppf}), \qquad \gamma_{\text{crit}}^2 = 1 - \alpha^{1/(n-1)}.$$
  - Окна с $\hat{p} \le p_{\text{crit}}$ помечаются как статистически незначимые (их $\psi, \chi$ не интерпретируются и визуально маскируются).

## 6. Двойная кросс-спектральная подсистема и архитектура длительных вычислений

По требованиям R1 и диссертационного исследования система реализует **оба** дополняющих друг друга метода межстанционного анализа.

### 6.1. Метод 1: Классический кросс-спектр Уэлча с двухфазным кэшированием

Чтобы избежать повторного расчёта БПФ для каждой из $\binom{49}{2} = 1176$ пар станций, вычисления разделены на две фазы:
1. **Фаза 1 (Постанционная, $O(N_{\text{ст}})$):** для каждой из 49 станций вычисляются и кэшируются на диск (`spectra_phase1/`) массивы оконных комплексных спектров $F_i(t_w, m, f_k)$ по выбранной компоненте (`X`, `Y`, `Z` или `Xm`, `Ym`) и **булева маска валидности сегментов `valid_i(t_w, m)`** (сегмент валиден при отсутствии разрывов `>3` мин и $\le 5\%$ пропусков по §3.2).
2. **Фаза 2 (Межпарная матричная с совместной маской, $O(1)$ перемножение кэшей):** для любой пары $(i, j)$ с неполным покрытием перекрёстный спектр **и оба автоспектра** вычисляются **строго на пересечении валидных сегментов** `mask_ij = valid_i & valid_j` с фактическим числом общих сегментов $K_{ij} = \sum_m \text{mask}_{ij}(t_w, m) \le \min(K_i, K_j)$:
   $$S_{ij}^{(ij)}(t_w, f) = \frac{1}{K_{ij} N_B}\sum_{m \in \text{mask}_{ij}} \sum_{k\in B} F_i(t_w, m, k)\,F_j^*(t_w, m, k), \qquad S_{ii}^{(ij)}, S_{jj}^{(ij)} \text{ — по тем же } m \in \text{mask}_{ij}.$$
   Это гарантирует неравенство Коши–Буняковского ($\gamma_{ij}^2 \le 1$) и корректный пересчёт $n_{ij}(K_{ij})$ и $\gamma_{\text{crit}}^2(n_{ij})$ для пар с несимметричными пропусками (при $K_{ij} < K_{\min}$ окно помечается невалидным). При расчёте динамической матрицы $49\times 49$ перемножение выполняется **пооконно / чанками по $t_w$** (ограничивая пиковое ОЗУ до десятков мегабайт вместо аллокации плотного тензора $49\times 49 \times T \times F$).
   На выходе формируются:
   - квадрат спектральной когерентности $\gamma_{ij}^2 = |S_{ij}^{(ij)}|^2 / (S_{ii}^{(ij)} S_{jj}^{(ij)})$ с порогом $\gamma_{\text{crit}}^2(n_{ij})$ (формула 25);
   - разность фаз $\Delta\phi_{ij} = \arg S_{ij}^{(ij)} = \phi_i - \phi_j$ (вычисляется только там, где $\gamma_{ij}^2 > \gamma_{\text{crit}}^2$);
   - **азимутальное волновое число $m$** для пар с продольным разносом **$|\Delta\lambda| \ge \Delta\lambda_{\min}$** ($\Delta\lambda_{\min} = 2^\circ\text{–}5^\circ$ в радианах, что исключает деление на ноль на меридиональных парах): $m = \Delta\phi_{ij} / \Delta\lambda$. В интерфейсе и отчётах явно учитывается пространственный $2\pi$-алиасинг ($|m_{\text{alias}}| = \pi / |\Delta\lambda|$, напр., при $|\Delta\lambda| = 10^\circ$ однозначный диапазон $|m| \le 18$);
   - **меридиональный градиент фазы и амплитуды** вдоль широтных профилей (например, скандинавско-восточноевропейская цепочка `HRN -> ABK/KIR/SOD -> LYC -> NUR/UPS -> HLP -> BEL -> LVV -> PAG -> PEG` для выявления резонанса силовых линий FLR).

### 6.2. Метод 2: Кросс-вейвлет преобразование (`XWT`) и вейвлет-когерентность (`WTC`)

Для нестационарных импульсных процессов (внезапные импульсы `SI`/`SSC`, фронты корональных выбросов и кратковременные пакеты Pc5/Pc6) реализуется непрерывное вейвлет-преобразование на базе комплексного вейвлета Морле ($\omega_0 = 6$):
1. **Политика разрывов `NaN` перед FFT-вейвлетом:** поскольку БПФ распространяет любой `NaN` на всю область времени и масштабов, пары $(x_i, x_j)$ предварительно пересекаются по совместной маске валидности и **разбиваются на непрерывные валидные подсегменты** (либо для коротких локальных интервалов допускается ограниченное заполнение с наложением **внутреннего конуса влияния разрыва `gap-COI`**, маскирующего искажённые масштабы вблизи разрыва наравне с краевым `COI`).
2. **Вычисление CWT и XWT:** $W_i(t, s)$ и $W_j(t, s)$ через быструю свёртку в Фурье-пространстве; кросс-вейвлет $W_{ij}(t, s) = W_i(t, s)\,W_j^*(t, s)$, локальная фаза $\arg W_{ij}(t, s)$ (визуализируется стрелками) и **конус влияния (`COI` + `gap-COI`)**, за пределами которого граничные эффекты искажают спектр.
3. **Вейвлет-когерентность (`WTC`):**
   $$R^2(t, s) = \frac{\left| S\!\left(s^{-1} W_{ij}(t, s)\right) \right|^2}{S\!\left(s^{-1} |W_i(t, s)|^2\right) \cdot S\!\left(s^{-1} |W_j(t, s)|^2\right)},$$
   где $S(\cdot)$ — оператор сглаживания по времени (окно Гаусса $\propto e^{-t^2/(2s^2)}$ через векторизованную FFT-свёртку) и по масштабу (дробно-окновое сглаживание на `NumPy`), а суррогаты AR(1) генерируются через `scipy.signal.lfilter` (с однопоточным BLAS внутри воркеров `ProcessPoolExecutor`).
4. **Значимость по методу Монте-Карло (основной источник длительности):**
   - По валидным подсегментам $x_i, x_j$ оцениваются коэффициенты авторегрессии $\alpha_1^{(i)}, \alpha_1^{(j)}$ (модель красного шума AR(1)).
   - В воркерах `ProcessPoolExecutor` генерируется $N_{\text{MC}} \in [300, 1000]$ пар независимых AR(1) суррогатов, для каждой рассчитывается `WTC`, и на каждом масштабе $s$ определяется 95%-й перцентиль $R_{95}^2(s)$ (внутри `COI`).

### 6.3. Трёхуровневая модель нагрузки и управление фоновыми задачами

| Уровень | Целевое время отклика | Операции | Механизм исполнения |
|---|---|---|---|
| **Tier 1 (Мгновенный)** | $< 0.3\text{ с}$ | Переключение станций/штормов, зум, пересчёт порогов $\alpha \in \{0.05, 0.01\}$, загрузка кэша из `user_cache/` | Синхронный ответ `FastAPI` из `Parquet`/`NPZ` кэша |
| **Tier 2 (Интерактивный)** | $< 2\text{ с}$ | Расчёт Варианта A/B для станции, 2D/3D Стокс, двухфазный кросс-спектр Уэлча (вкл. 1 176 пар при прогретой Фазе 1) | `FastAPI` threadpool (`NumPy`/`SciPy` освобождают GIL) |
| **Tier 3 (Асинхронный)** | Десятки секунд — минуты | `XWT`/`WTC` + 300–1000 суррогатов Монте-Карло, динамическая матрица Уэлча $49\times 49$ без кэша, MC-калибровка эффективного $n$ | Очередь `ProcessPoolExecutor` + WebSocket/SSE прогресс + дисковый кэш |

**Протокол асинхронной задачи (`JobManager`):**
1. Запрос `POST /api/jobs/wtc` формирует канонический ключ кэша `cache_key = sha256(core_version + canonical_params_json)` (единый стандарт с §4.2).
2. Если результат уже есть в `user_cache/` (и/или `cache_index` в `runtime.sqlite`), немедленно возвращается `status: "cached"` со ссылкой на результат.
3. Иначе задача помещается в `ProcessPoolExecutor` (с однопоточными ограничениями BLAS `OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, `NUMEXPR_NUM_THREADS=1`), клиенту возвращается `job_id`, а прогресс (`progress_pct`, `stage`, `eta_sec`) передаётся от воркеров через **`multiprocessing.Manager().Queue()`** (или SQLite-поллинг) и транслируется по `WebSocket` (`/ws/jobs/{job_id}`) или `SSE` (`/api/jobs/{job_id}/events`).
4. **Отмена (`DELETE /api/jobs/{job_id}`):** устанавливает разделяемый флаг **`multiprocessing.Manager().Event()`** (сериализуемый под Windows `spawn`, в отличие от голого `multiprocessing.Event`) или файловый/SQLite `cancel_token`, который проверяется между батчами Монте-Карло; прерванная задача очищает временные файлы и переводит статус в `cancelled` в `runtime.sqlite`.

## 7. Архитектура фронтенда (`React/TS`) и офлайн-карты

Фронтенд представляет собой одностраничное приложение (`React 18 + TypeScript + Vite`), полностью собранное в статический бандл без каких-либо внешних CDN-запросов (шрифты, иконки и геоданные встроены локально).

### 7.1. Модули интерфейса и синхронизированная многопанельная лента

1. **Панель навигации и конфигурации эксперимента:**
   - Выбор штормового эпизода (`Oct 04–05`, `09–11`, `21–23`, `30–31`), станции (или пары/меридиональной цепочки), диапазона (`Pc5`, `Pc6` с выбором $T_{\max}$), метода оценивания (`Вариант A: Welch / Multitaper`, `Вариант B: FFT-маска / Butterworth SOS`), СК (`XYZ` геогр. / `XmYm` магн.), оверсэмплинга $m \in \{1, 4, 8\}$ и уровня значимости $\alpha$.
   - Переключатель баллистического сдвига `SOLAR-1` (`L1 raw` vs `Сдвиг к Земле: авто V_x / ручной лаг в минутах`).
2. **Синхронизированный комплекс временны́х панелей (`ECharts` / `uPlot` с общей осью UTC):**
   - *Панель 1 — Космическая погода:* `SOLAR-1` ($B_z$ GSM, $|B|$, $V_{\text{sw}}$, $P_{\text{dyn}}$ в нПа) + `OMNI` ($AE/AL/AU$, если доступно на выбранные даты) + `OULU NM` ($\Delta N / N_0$, % — Форбуш-эффект).
   - *Панель 2 — Магнитометр:* исходные и отфильтрованные ряды `Pc5`/`Pc6` по $X, Y, Z$ (с подсветкой интерполированных участков $\le 3$ мин и вырезанных краёв $T_{\text{cut}}$).
   - *Панель 3 — Поляризация Стокса:* временна́я эволюция $I, p, \psi, \chi, \varepsilon, \gamma^2$ с горизонтальной пороговой линией $p_{\text{crit}}$ и **автоматическим маскированием (затемнением/разрывом линии)** интервалов, где $\hat{p} < p_{\text{crit}}$ (меняется мгновенно на клиенте при смене $\alpha$).
   - *Панель 4 — Спектрограмма и Кросс-анализ:* динамический спектр мощности, когерентность и разность фаз Уэлча $\gamma_{12}^2(t,f), \Delta\phi_{12}(t,f)$, а также 2D-карты **`XWT`/`WTC`** с наложенным контуром `COI`, контуром 95% значимости Монте-Карло и векторными стрелками сдвига фаз.
3. **Менеджер фоновых задач и панель экспорта:** прогресс-бар активных MC-расчётов с кнопкой отмены; экспорт любого графика/карты в **векторный `SVG`** и **`PNG` (300 DPI)**, а числовых рядов/таблиц — в **`CSV`**.

### 7.2. Офлайн-первая интерактивная карта 49 станций

Карта должна одновременно отображать **Европу (37 станций, `28.3°N`–`77.0°N`, долготный размах `~46,1°` от `-16,40°` `GUI` до `+29,70°` `IZN`)** и **Канаду (12 станций, `43.9°N`–`74.7°N`, долготный размах `~70,7°` от `-123,42°` `VIC` до `-52,68°` `STJ`)**, что при одновременном показе охватывает **`~153°` (`153,12°`, от `-123,42°` до `+29,70°`)** по долготе (с пересчётом `[0, 360)` $\to$ `[-180, 180]`), допускать плавное масштабирование на отдельные регионы (например, Скандинавию и Украину `LVV`) и **гарантированно работать без интернета** (в частности, на защите диссертации).

- **Единая 100% офлайн-стратегия (`D3-geo` + `world-atlas/world-110m.topojson` ~150 КБ):**
  - Вся геометрия материков и границ рендерится 100% офлайн через **`D3-geo` (`topojson-client` + встроенный `world-110m.topojson`)** в равновеликой или конической проекции Ламберта (`geoConicConformal` / `geoAzimuthalEqualArea`), что **устраняет высокоширотные искажения проекции Web Mercator** (`HRN` `77.0°N`, `RES` `74.7°N`) и даёт нативные SVG-элементы на 60 FPS с идеальным экспортом в векторный `SVG` для диссертации.
  - Коммерческие/внешние тайлы (`Leaflet` + OSM/CartoDB) **не используются** в основном контуре: при внешней работе `Leaflet` требовал бы дополнительного адаптера `topojson-client`, вносил бы искажения Web Mercator на широте `77°N` и расходился бы по геометрии с векторным `SVG`-экспортом `D3-geo`.
- **Научные слои на карте (синхронизированы с ползунком времени UTC):**
  1. **Эллипсы поляризации Стокса** на каждой из 49 станций: полуоси в пропорции $|\varepsilon| = b/a$, ориентация по азимуту $\psi$, радиус пропорционален $\log(I)$ или $\sqrt{I}$, цвет и стрелка задают направление вращения (`CW` при $V > 0$ vs `CCW` при $V < 0$), а станции с $\hat{p} < p_{\text{crit}}$ или недостатком данных отображаются серым нейтральным маркером.
  2. **Линия терминатора день/ночь и полудня `MLT = 12`:** астрономический расчёт положения Солнца на выбранный момент UTC с наложением полупрозрачной ночной полусферы и меридиана `MLT = 12` (критично для визуализации смены знака вращения $\varepsilon$ на утренней и вечерней сторонах магнитопаузы при КГИ).
  3. **Интерактивный выбор пары и дуги когерентности:** клик по первой и второй станции выбирает пару для кросс-спектра; на карте рисуется геодезическая дуга, цвет и толщина которой кодируют $\gamma_{12}^2$, с всплывающей меткой $\Delta\phi_{12}$ и азимутального числа $m$.

## 8. Упаковка под Windows, безопасность и веб-развёртывание

### 8.1. Сборка настольного дистрибутива для Windows (приоритет №1)

1. **Сборщик:** `PyInstaller --onedir` (единая папка с `GeoMagAnalyzer.exe` и библиотеками; упаковываются `NumPy`, `SciPy`, `PyArrow`, `pywebview`, `frontend/dist/` и `data/processed/`; холодный старт `1–2 с` без задержки самораспаковки `--onefile` и с минимальным риском ложного срабатывания антивируса). Обязателен вызов `multiprocessing.freeze_support()` в точке входа `launcher.py` и однопоточный BLAS (`OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, `NUMEXPR_NUM_THREADS=1`) в воркерах.
2. **Разделение статики и пользовательских данных:**
   - Внутри каталога установки/бандла `data/processed/` (`catalog.sqlite`, `.parquet`) и `frontend/dist/` открываются строго **read-only** (безопасно при обновлении инсталлятора и запуске с носителей без прав записи).
   - Изменяемые `runtime.sqlite` (`jobs`, `cache_index`) и пользовательский кэш `user_cache/` записываются в **`%LOCALAPPDATA%\GeoMagAnalyzer\`** (для `Inno Setup`) либо в `./user_data/` (для портативного `.zip` при наличии прав записи с автоматическим фолбэком в `%LOCALAPPDATA%\GeoMagAnalyzer\`).
3. **Два формата поставки без прав администратора:**
   - **Портативный `.zip` (`GeoMagAnalyzer_Portable_Win64.zip`):** распаковка в любую пользовательскую папку (вплоть до флешки) и запуск `GeoMagAnalyzer.exe` двойным кликом; никаких записей в `Program Files` или системный реестр.
   - **Установщик `Inno Setup` (`GeoMagAnalyzer_Setup.exe`):** настроен с `PrivilegesRequired=lowest` (установка в `{localappdata}\Programs\GeoMagAnalyzer` и ярлык на рабочем столе текущего пользователя без запроса UAC).
   - **Управление процессом в `--browser` (`console=False`):** UI содержит кнопку «Остановить сервер / Выход» (`POST /api/shutdown` с session-token) и/или иконку системного трея Windows для чистого завершения сервера без диспетчера задач.
4. **Комплект данных и runtime-кэш:** дистрибутив поставляется с уже выполненным ETL (`data/processed/`); спектры Фазы 1 Уэлча и результаты `XWT`/`WTC` сохраняются по мере расчёта в пользовательском `user_cache/` для мгновенного повторного открытия.

### 8.2. Развёртывание в режиме веб-сервиса

1. `FastAPI` обслуживает статику `React/TS` по `/` и API/WebSocket по `/api/*`, `/ws/*`.
2. Рекомендуемая конфигурация: **`uvicorn geomag_api.main:app --host 0.0.0.0 --port 8000 --workers 1`** за `Nginx`/`Caddy` с поддержкой WebSocket (`proxy_http_version 1.1; Upgrade; Connection "upgrade"`). Использование одного API-воркера (`--workers 1`) обязательно при хранении пула и отмен `JobManager` в памяти процесса (многоворкерный `gunicorn` допускается только при выносе состояния задач и токенов отмены во внешний брокер `Redis`/БД).
3. Меры безопасности:
   - привязка локального десктоп-сервера строго к `127.0.0.1`;
   - **совместимая с `WebSocket`/`SSE` защита от локального CSRF:** строгая валидация заголовков **`Origin`/`Host`** на всех REST и WebSocket-ручках + одноразовый bootstrap-токен в URL/query при старте (`?token=...`), обмениваемый на `SameSite=Strict` `HttpOnly` cookie (так как браузерные `WebSocket` и `EventSource` API не позволяют передавать произвольные кастомные HTTP-заголовки; для мутирующих REST-запросов `POST`/`DELETE`, включая `/api/shutdown`, дополнительно проверяется `X-Session-Token`);
   - в публичном веб-режиме — ограничение числа воркеров `ProcessPoolExecutor`, тайм-аут и квота $N_{\text{MC}} \le 1000$ на запрос, `read-only` режим относительно базового набора данных.
